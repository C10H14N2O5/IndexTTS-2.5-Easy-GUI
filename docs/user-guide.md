# 使用指南

本文按界面上的页面顺序介绍：[声音库](#声音库) → [语音合成](#语音合成) → [数据准备](#数据准备) → [LoRA 训练](#lora-训练) → [盲测对比](#盲测对比) → [导出 GPT 检查点](#导出-gpt-检查点)。安装和启动见 [安装与配置](installation.md)。

## 声音库

在“🎙️ 声音库”页保存常用的参考音频，之后在合成页直接选用。

- 上传或录制一段参考音频。建议用短而干净的单人语音，可以用 Trim 裁剪。
- “参考音频文本”可以不填。它指的是参考音频里实际说的话，不是要合成的内容。
- 保存后文件复制到 `voices/`，重启后仍然可用。
- 同一页还有**情绪描述库**：把常用的情绪文字描述保存起来，供“情绪描述”模式调用，保存在 `emotion_descriptions/`。

## 语音合成

“🔊 语音合成”页分为**单条合成**和**对话合成**两种。页面上方的全局设置（语言、解码参数、情绪、CUDA 运行设置）由两种模式共用。

### 单条合成

1. 在“快捷样本选择”中选一个已保存的音色，或选“无”后直接上传或录制参考音频。
2. 输入待合成文本，选择语言（中文、英文、日文、西班牙文、阿拉伯文）。
3. 可选：在“LoRA 适配器”中加载训练好的适配器或检查点。
4. 点击“⚡ 生成语音”。勾选“保存到 outputs”会把结果保存到 `outputs/`。

**长文本**：在“长文本 / 分段”中选择分段模式（推荐“段落 / 句子自动分段”，也可以按句号、段落、行或说话轮次分段），每段分别合成，再按设置的间隔拼接成一个 WAV。

### 情绪控制

| 情绪模式 | 说明 |
| --- | --- |
| 跟随音色参考 | 情绪和语调跟随参考音频本身 |
| 情绪参考音频 | 音色来自参考音频，情绪来自另一段音频 |
| 情绪向量 | 直接设置 8 个维度：高兴、愤怒、悲伤、害怕、厌恶、低落、惊讶、平静；预设可以一键填入，之后仍可微调 |
| 情绪描述 | 用文字描述情绪和语调（由 QwenEmotion 理解），可以从情绪描述库选用 |

“情绪权重（Alpha）”控制情绪的强度，调得越高不一定越自然。“随机情绪采样”会增加变化，但每次结果更难复现。

### 对话合成

在“对话合成”中逐轮编排多人对话：每一轮分别选择音色、填写文本，并选择一种情绪来源（情绪向量预设或情绪描述）。每行都可以插入、复制、上移、下移、清空或删除。最后点击“⚡ 生成对话”，各轮按“对话轮次间隔”拼接成一个 WAV。

### 常用参数

| 参数 | 作用 |
| --- | --- |
| 时长系数 | 1 为正常；小于 1 语速更快，大于 1 更慢 |
| 文本规范化 | 合成前把数字、日期、单位等转换成读法 |
| 自动分段间隔 | 长文本自动拆分后，段与段之间插入的静音 |
| 每段最大文本 Token 数 | 文本超过这个长度就拆分 |
| 启用采样 | 关闭后结果更稳定、更可复现 |
| 采样温度 | 越低越保守，越高变化越多 |
| Top P / Top K | 限制每一步可选的候选范围 |
| 束搜索宽度 | Beam search 的宽度 |
| 重复惩罚 | 抑制重复的发音片段 |
| 最大声学 Token 数 | 限制单段生成的长度 |

### CUDA 运行设置

BF16、GPT 潜变量路径、torch.compile（Triton）、FlashAttention GPT 加速，会根据当前环境决定是否可用，设置会保存下来供下次启动使用。首次启用 torch.compile 时需要编译，会比较慢。FlashAttention 需要同时开启 BF16 并安装 Triton。各组件的说明见 [可选加速组件](installation.md#可选加速组件)。

页面底部可以查看生成进度、显存占用和内嵌控制台；顶部的“卸载模型”按钮可以释放显存。

## 数据准备

“📂 数据准备”页内嵌了一个**听音校对工作台**，用来为训练语料补全文本、逐条核对。

### 准备语料

语料需要**事先切好片**，每段音频配一个同名的 TXT：

```text
my_voice/
├─ 001.wav
├─ 001.txt
├─ 002.wav          # 没有 TXT 的音频可以自动识别
└─ session_02/
   ├─ 001.wav
   └─ 001.txt
```

- 会扫描所有子目录，支持 WAV、FLAC、MP3、M4A、OGG、AAC。不同子目录里的同名文件按相对路径区分。
- TXT 写的必须是音频里**实际说出的话**。例如日语音频要用日语原文，不能用翻译字幕。
- 原音频不会被修改。

### 操作流程

1. 创建或选择一个项目，填写语料目录和训练语言，点击“💾 保存项目”。
2. 在工作台点击“**识别缺失文本**”。程序会为整个目录（含子目录）里缺少文本或文本为空的音频生成 TXT，已有内容的跳过。识别中途可以停止，已完成的结果会保留，下次运行时继续。
3. 逐条试听，修改文本：
   - “保存”只保存文本；
   - “保存并下一条”保存后，还会把这一条标记为已校对，然后跳到下一条；
   - “重新识别当前条目”把识别结果放进编辑框，**不会自动保存**，检查后再手动保存。
4. 全部完成后点击“**更新训练清单**”，然后去“LoRA 训练”页。

快捷键：`Ctrl+S` 保存，`Ctrl+Enter` 保存并下一条，`Alt+Space` 播放 / 暂停。如果快捷键被浏览器占用，使用对应的按钮即可。

### 为什么保存后还要更新训练清单？

训练读取的是训练清单（`training/datasets/<项目>/manifest.jsonl`），清单里的文本是生成那一刻的快照。保存 TXT 不会自动更新清单。

- 点“更新训练清单”时，会读取当前已保存的 TXT 生成清单，不会重新识别。部分音频可能因时长不符合要求被过滤，所以**扫描到的文件数不一定等于训练样本数**，请看清单里显示的有效样本统计。
- 语料改动后，清单会显示“待更新”；清单过期时，GUI 不会开始训练。
- 训练进行中可以继续校对，但要等训练结束才能更新清单。

### 文本保护

- TXT 保存为 UTF-8。第一次修改某个已有 TXT 时，原文会备份到语料目录的 `.proofread/backups/`。
- 校对进度保存在 `.proofread/state.json`。“已校对”只是进度标记，不影响这一条是否参与训练。文本改动后，旧的标记会失效。
- 如果 TXT 在别处被修改过，保存时会提示冲突，不会直接覆盖。请先复制要保留的内容，再重新加载磁盘上的文本。
- 切换条目或目录时，如果有未保存的修改，会先询问你如何处理。

### 关于语音识别

所有识别功能都使用 SenseVoiceSmall Q8，在 CPU 上运行，自动判断语言。这包括数据准备、声音库、合成页的参考音频以及训练的评估参考音频。请求按顺序逐个处理，单条超时 180 秒。识别前会先把音频转换成临时副本，因此中文路径和文件名不受影响。识别失败时不会改用其他模型，日志在 `.runtime/asr/logs/`。

### 准备验证集

1. 先保存训练语料目录和语言，再在「数据准备」页切换到「验证集」。可保存建议目录 `validation/<项目名>/`，或选择已有服务器目录。GUI 引用原目录，识别和校对直接保存同名 TXT。
2. 使用与训练集相同的识别、试听和校对流程。完成后点击「更新验证清单」，生成独立的 `training/datasets/<项目名>/validation.jsonl`。工作台显示总数、有效数、过滤数和缺少文本的数量。
3. 使用未参与训练的录音片段。开启验证后，训练会检查验证清单是否有效，以及两份清单中是否存在相同文件或字节完全相同的副本。剪切或重新编码的重复片段需要自行排除。

## LoRA 训练

当前训练器是**实验性的** GPT LoRA：只训练 IndexTTS 中 GPT 模块的 LoRA 参数，其余部分保持不变；训练目标是还原声学 token。训练出来的是一个“适配器”，使用时仍需要原始的 IndexTTS 模型和参考音频。

### 开始训练

1. 在“🚀 LoRA 训练”页选择一个已经更新过训练清单的项目，给这次训练起一个“适配器名称”。
2. 选择显存预设，点击“⚡ 自动调参”。它会根据语料统计给出一组初始参数，但**不会实际测量你的显存**，只是一个起点。
3. 检查训练长度（按步数或按轮数）、LoRA 秩、Alpha、丢弃率、学习率、梯度累积和保存间隔，然后点击“💾 保存项目”。
4. 可选：在“评估音频与 TensorBoard”中填写评估文本和参考音频。每次保存检查点时会生成一段试听音频。
5. 点击“🚀 开始训练”。可以随时停止，也可以打开 TensorBoard 查看曲线。

### 验证损失

- 首次保存验证目录会启用「验证损失」。关闭开关时可照常训练，也可以在没有验证集的项目上直接训练。目录、清单和间隔设置会保留。点击「保存项目」保存开关和间隔。
- 间隔填 `0` 或留空时随检查点验证，也可填写正整数，指定每多少个优化器步验证一次。正常训练结束时会验证最终权重。每轮验证使用当前 LoRA 跑完整验证集，按音频样本平均声学损失。
- 在 TensorBoard 的 **Custom Scalars** 中打开 **Loss → Training and validation**，同图查看 `train/loss_ema` 和 `validation/loss`。对比同一验证集上的趋势。训练损失持续下降而验证损失持续上升时，可能已经开始过拟合。更换验证集时可在 **Text** 中查看 `validation/dataset` 的清单指纹和样本数。
- 若验证失败，训练会保留当前步的检查点后停止。修正问题并更新验证清单后，可从该检查点续训。

### 输出

```text
training/outputs/<适配器名称>/
├─ checkpoint-step-000100/   # 按保存间隔生成
├─ ...
└─ final_adapter/            # 训练完成后的最终结果
```

在“继续训练的检查点”中选择一个检查点即可续训。在语音合成页的“LoRA 适配器”中，可以加载任意检查点或 `final_adapter`。

### 建议

- 先跑一次短训练并试听效果，再安排长时间训练。
- 比较不同参数时，请使用不同的适配器名称，并用**同一段参考音频**和**同一段训练中没出现过的文本**来试听。
- 不要只看 loss 选择权重，以耳朵听到的效果为准。想确认新权重是真的变好还是变差，可以用 [盲测对比](#盲测对比)。

## 盲测对比

“🎧 盲测对比”页用盲听配对比较两个适配器 A 和 B，判断新训练的 LoRA 是真的变好了还是变差了。任何一边都可以选“无（原始模型）”，或 `training/outputs/` 中的任意 `final_adapter`、`checkpoint-step-*`，但 A 和 B 不能相同。

### 新建测试

1. 可选：填写测试名称。选择适配器 A 和适配器 B。
2. 从声音库选择参考音色。如果它有同名的 `.txt` 文本，两边都会使用。
3. 选择语言，输入测试句子（每行一句），设置每句生成次数（1–5，默认 2）。页面会显示“N 句 × R 次 = N·R 组，共需合成 2·N·R 段音频”。
4. 点击“⚡ 生成测试音频”。

解码参数和 CUDA 运行设置沿用“语音合成”页当前的全局设置，情绪固定为“跟随音色参考”。程序先生成所有 A 的音频，再生成所有 B 的，所以模型最多加载两次。同一句、同一次生成中，A 和 B 使用相同的随机种子，这能减少但不能消除随机性带来的差异。“⏹️ 停止”会在当前这段完成后停下，之后（包括重启 GUI 后）可以点“▶ 继续生成”接着生成。

### 评分

在“已保存的盲测”中选择测试。每一组显示目标文本、可播放的参考音频，以及同一句话的“样本 1”和“样本 2”。A、B 的先后顺序是随机的，并且保持平衡：一半的组里 A 是样本 1。

评分分五档：样本 1 明显更好 / 样本 1 略好 / 差不多 / 样本 2 略好 / 样本 2 明显更好。评分立即保存，可以用“上一组”“下一组”“下一个未评组”切换；揭晓前随时可以修改。

### 揭晓与解读结果

点击“🔓 揭晓结果”并确认后，评分会被锁定，未评分的组不计入。结果包括：

- A 更好、B 更好、差不多各有几组；
- 平均偏好，从 −2（偏向 A）到 +2（偏向 B），附标准误；
- 不计“差不多”的双侧精确符号检验 p 值。p < 0.05 表示差异显著，否则显示“没有发现显著差异”；
- 每一组的明细表，标明当时样本 1 是哪一边。

“没有发现显著差异”不代表两者完全一样，只说明这次测试没能把它们区分开。

### 建议

- 用较短的句子（约 5–15 秒），至少评 10–20 组。不计“差不多”的组至少要有 6 组，结果才可能显著：6:0 时 p≈0.031，5:0 时只有 p≈0.063。
- 生成盲测音频期间，尽量不要在其他页面合成，否则可能导致额外的模型重载。
- 在常见显卡上，每段音频的生成时间大约是音频时长的 2 倍，另加模型加载时间。总段数在开始前会显示出来。
- 盲测只是轻度保密：A、B 的身份只在本页隐藏（音频文件名是随机的）。控制台和全局状态可能显示适配器名称，但不会显示哪个样本对应哪一边。

### 存储

每个测试保存在 `outputs/abx/<YYYYmmdd_HHMMSS>/` 中，包括 `session.json`、参考音频的副本（`reference.<扩展名>`）和 `clips/<随机 ID>.wav`。“删除输出音频”按钮只删除直接位于 `outputs/` 下的文件，不会动 `outputs/abx/`。要删除某个测试，直接删除它的文件夹。

## 导出 GPT 检查点

“📦 导出 GPT 检查点”页把 LoRA 合并到原始 GPT 权重中，生成一个完整的 `.pth` 文件，供 ComfyUI 等工具直接加载。合并在后台用 CPU 进行，不占用显卡，期间界面可以正常使用。

### 在界面中导出

1. 选择一个适配器（`final_adapter` 或某个 `checkpoint-step-*`），也可以填写或浏览自定义的适配器目录。
2. 选择导出方式：
   - **通过浏览器下载**（默认）：填写文件名，导出并验证完成后，下载 `.pth` 和验证报告 `.merge.json`。
   - **保存到服务器路径**：填写运行 GUI 那台电脑上的完整 `.pth` 路径，或点击“在服务器上另存为”。
3. 在“高级设置：底模与验证”中，确认训练时使用的原始 FP32 底模和 `config.yaml`。如果填写了“待比较的部署底模”，会先检查两者的 SHA-256 是否一致。
4. 点击导出，查看进度和日志。导出可以取消；只有成功并通过验证的导出，才会显示下载链接。

导出时会检查权重结构、数值，以及合并前后的输出误差。已有的文件不会被覆盖。训练和导出不能同时进行，一次也只能运行一个导出任务。导出日志在 `.runtime/export/logs/`。

### 用命令行导出

```powershell
.\.venv\Scripts\python.exe -B tools\merge_lora_to_pth.py `
  --base models/IndexTTS-2.5/gpt.pth `
  --config models/IndexTTS-2.5/config.yaml `
  --adapter training/outputs/my_voice/final_adapter `
  --output outputs/merged/my_voice.pth
```

可以加 `--expected-base <部署用的 gpt.pth>`，检查部署环境的底模与训练底模是否一致。

### 在 ComfyUI 中使用

导出的文件只替代 GPT 权重，其余模型文件和参考音频仍然需要。对于提供 `GPT Checkpoint Selector` 节点的 IndexTTS-2.5 插件：

1. 把导出的 `.pth` 放进 ComfyUI 的 `models/IndexTTS-2.5/gpt_checkpoints/`，保留原来的 `gpt.pth`；
2. 刷新检查点选择节点，选择这个文件，连接到合成节点的 `gpt_checkpoint` 输入。

合并后的模型与实时加载 LoRA 的效果可能有细微差异，请试听确认。
